# IDD-0003.spec-streaming-structural-scan-and-recovery

## Intent

Process books larger than an LLM context window as a resumable streaming
structural parse with application-owned state.

## Related Specifications

- IDD-0001
- IDD-0002

## Behavior

- The body scan advances monotonically through pointer order. Each scan window
  has read-only previous context, one writable decision zone, and read-only
  look-ahead.
- Every pointer belongs to the decision zone of exactly one primary window. It
  may appear in context for adjacent windows but is classified at most once by
  the ordinary scan.
- The scan state includes a cursor and committed boundary, active heading stack,
  recent accepted headings, next expected TOC entries, numbering information,
  accepted annotations, and deferred candidates.
- A committed boundary cannot be changed by a later ordinary scan. A candidate
  near the decision-zone boundary can be deferred until sufficient forward
  context is available.
- The application supplies global document position, current structure, recent
  headings, the current heading level, the pointer-and-level chain of active
  ancestor headings, and only nearby relevant TOC entries with each semantic
  decision so a window start is not interpreted as a chapter start.
- Heading hierarchy is maintained by application logic: a new level 1 clears
  lower levels, a level 2 retains level 1 and clears level 3, and a level 3
  retains its ancestors.
- Workflow checkpoints exist after import, segmentation, TOC detection, TOC
  parsing, scanning progress, structure validation, and completion. Restart
  resumes from the committed boundary without replaying semantic calls for
  committed windows.
- A configuration change that affects segmentation or pointer IDs invalidates
  an existing scan state. An exporter-only change does not require a semantic
  rescan; a model-profile change may reuse compatible domain state.
- After scanning, deterministic validation checks annotation consistency,
  heading order and levels, hierarchy and numbering anomalies, TOC ordering,
  duplicate mappings, TOC/body separation, and repeated-running-header errors.
- A local repair workflow may reconsider only a reported suspicious range with
  surrounding context, apply validated changes, and repeat global validation.
  Repair cycles are bounded by configuration.
- If a semantic step exhausts its retries, the application does not invent an
  annotation. It uses a deterministic fallback when available, leaves the area
  unresolved, or completes with warnings.

## Product-Significant Architecture And Constraints

Long-term book memory belongs to persisted application state, not LLM
conversation history. No required semantic operation may require the whole book
in its input.

## Non-goals

- Reclassifying committed history during a normal subsequent scan.
- Requiring human intervention for ordinary ambiguity in the main workflow.

## Acceptance Criteria

- A book substantially larger than the model context window can be processed in
  windows without duplicate overlap classification.
- A restart continues from the latest committed window without repeating its
  semantic calls.
- A window beginning inside a chapter does not turn its initial body text into a
  heading merely due to its prompt position.
- Window heading classification accepts only pointer-to-level assignments for
  eligible pointers; pointers omitted from the result remain body by default.

## Verification

- Verify window ownership, boundary deferral, restart, local repair, hierarchy,
  duplicate-overlap, mid-chapter-window scenarios, and reconstruction of the
  current level and active ancestor chain in each semantic input.
