# IDD-0003.spec-streaming-structural-scan-and-recovery

## Intent

Process books larger than an LLM context window as a resumable streaming structural parse with application-owned state.

## Related Specifications

- IDD-0001
- IDD-0002
- IDD-0004

## Behavior

- The body scan advances monotonically through pointer order. Each primary window contains read-only previous context, one owned decision zone, and read-only look-ahead.
- Every pointer belongs to the decision zone of exactly one primary window. Overlap is context only and never creates a second ordinary ownership opportunity.
- Window planning is governed by deterministic approximate text budgets rather than physical pages or pointer counts alone. Pointer-count limits may exist only as safety caps.
- One anomalously large pointer uses a deterministic bounded model representation so model input remains bounded while the scan still makes progress.
- Candidate detection receives confirmed breadcrumb text, previous context, the complete decision zone, eligibility metadata, and look-ahead. It returns only local candidate numbers.
- Candidates are normalized into source order and verified sequentially, one semantic call per candidate.
- The verifier uses confirmed breadcrumb text and bounded centered context from the immutable source. Its local context may extend outside the primary window because that context is read-only.
- A temporary heading stack starts from the committed stack at the beginning of the window. Accepted semantic headings and existing deterministic headings update this temporary stack in source order, so later verifiers see the newest confirmed structure.
- Preliminary detector candidates are not annotations and are never durable state.
- A primary window is committed only after candidate detection succeeds, every candidate has either been verified or recorded as unresolved after verifier retries, and application validation has completed.
- Exhausted candidate-detector retries do not advance cursor or committed boundary and produce an explicit window failure. Restart may retry that uncommitted window.
- Exhausted verifier retries leave only that candidate unresolved, do not create a synthetic body annotation, and do not block later candidates in the same window.
- Committed windows are not replayed after restart. An uncommitted window may be processed again.
- The new heading workflow does not create DeferredBoundaryCandidate. Existing persisted deferred state remains readable for compatibility and can be removed separately after migration confidence is established.
- After scanning, deterministic validation checks annotation consistency, hierarchy, numbering anomalies, TOC ordering, duplicate mappings, TOC/body separation, and repeated-running-header errors.
- A bounded local repair workflow may reconsider only validated suspicious ranges.

## Product-Significant Architecture And Constraints

Long-term book memory belongs to persisted application state, not LLM conversation history. Models propose and verify local hypotheses; the application owns pointer identity, hierarchy, cursor, validation, retry policy, and commit.

## Non-goals

- Reclassifying committed history during a normal subsequent scan.
- Exactly-once persistence for each individual verifier call inside an uncommitted window.
- Using physical pages as the primary windowing mechanism.

## Acceptance Criteria

- A large book can be processed in bounded windows without duplicate overlap classification.
- Restart continues from the latest committed boundary without repeating semantic calls for committed windows.
- Candidate detector failure cannot silently turn a decision zone into body.
- Earlier accepted headings and deterministic headings inside a window affect breadcrumbs for later candidate verification.
- A candidate near a primary-window edge can receive verifier context from outside that primary window.
- A single huge pointer cannot create unbounded model input and cannot prevent cursor progress.

## Verification

Verify primary-window ownership, text budgets, huge-pointer bounding, contextual detector input, source-order candidate normalization, sequential verifier breadcrumbs, deterministic headings between candidates, detector failure, verifier failure, and restart before/after commit.
