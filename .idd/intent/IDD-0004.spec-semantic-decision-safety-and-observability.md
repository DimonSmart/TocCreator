# IDD-0004.spec-semantic-decision-safety-and-observability

## Intent

Use local, comparatively small models only for narrow semantic judgments while keeping book state, validation, retries, and output under application control.

## Related Specifications

- IDD-0001
- IDD-0002
- IDD-0003

## Behavior

- Each semantic operation has one narrow purpose and a typed result. Generic streaming heading recognition uses two operations: `window-heading-candidate-detection` and `heading-candidate-verification`.
- Candidate detection receives model-visible breadcrumb text, ordinary previous context, the full numbered decision zone, eligibility metadata, and look-ahead. Previous/look-ahead are strictly read-only.
- Stable pointer IDs are application-only and absent from both heading model payloads. The application maps local decision-zone numbers back to stable pointers.
- Candidate detection returns only an array of local candidate numbers. It does not return levels, annotations, reasons, confidence, or deferrals.
- Candidate verification receives exactly one candidate, current confirmed breadcrumb text, and bounded context before/after. It does not receive a proposed level, detector reasoning, detector confidence, or the other candidates.
- Verifier output is either reject with no level or accept with independently selected level 1 through 3.
- Typed results are validated before use. Invalid output retries only the affected detector or verifier operation.
- Detector retries are window-critical: exhausted retries leave the window uncommitted. Verifier retries are candidate-local: exhausted retries leave that candidate unresolved and processing continues.
- Profiles support JSON Schema, structured output when supported, and optional temperature. Provider JSON mode never replaces application validation.
- Diagnostics record operation, workflow step, model/profile, primary-window identity, application-side candidate pointer for verifier, selectable local numbers, typed result, validation failure, retry count, and elapsed time.
- Raw prompts and responses may be retained only through an explicitly enabled debug path. Credentials never enter diagnostics, scan state, or exception text.
- Project data separates immutable source, domain annotations, workflow state, diagnostics, and final Markdown output.

## Product-Significant Architecture And Constraints

The product is a streaming structural parser that uses models for local judgments. Models do not own stable IDs, book state, annotations, hierarchy, cursor, or Markdown output.

## Non-goals

- Giving a model the full book as required context.
- Using model confidence as an objective probability.
- Recovering malformed model JSON with a general hand-written parser.
- Returning stable pointer IDs from the two heading semantic operations.

## Acceptance Criteria

- Previous context and look-ahead text reach candidate detection while remaining unselectable.
- Stable pointer IDs of context, decision-zone elements, candidates, and ancestors are absent from serialized heading model input.
- Invalid candidate numbers, duplicates, and invalid verifier level combinations are rejected and retried locally.
- Empty candidate detection requires no body decisions and can commit the window.
- Operation diagnostics distinguish `window-heading-candidate-detection` from `heading-candidate-verification`.
- OpenAI-compatible provider integration remains provider-neutral.

## Verification

Verify contextual model payloads, ID hiding, read-only eligibility, duplicate/invalid candidate numbers, verifier accept/level dependency, provider options, malformed JSON, credential safety, operation-specific retries, and debug-only raw transcripts.
